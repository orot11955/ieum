# 개인 관리 웹 · 기능 명세

- 개정: 2026-09-22
- 상태: 제품 설계안. 기능·API·보안 테스트는 아직 구현하지 않았다.

## 1. 범위와 운영 기본값

이음은 내부 관리 프론트엔드와 백엔드가 있는 개인 앱이다. Core는 일부 해석과 정리 판단을 보조한다. 외부 독자용 블로그는 별도이며 발행 Delivery API를 소비한다. [기존 제품 범위](vision-and-scope.md)를 유지한다.

초기 운영안은 **자가 호스팅 1인 사용 + 초대형 계정 확장**이다. 공개 회원가입은 끈다. 계정마다 별도 개인 Workspace를 만들고, 누군가를 서비스에 초대하는 동작은 내 기록을 공유하는 동작이 아니다. 공동 편집·조직·과금·소셜 기능은 첫 제품 범위 밖이다. 여러 계정 사용 전 격리 테스트를 통과해야 한다.

기능 단계 표기: F=웹 기반, P=개인 관리, D=문서 작업, R=발행, X=후속 확장. F/P/D/R은 제품 개발 단계이며 기존 M0/M1 Core Lab을 대체하거나 즉시 전부 구현하라는 뜻이 아니다.

## 4. 로그인·회원 관리 UX

회원 상태는 INVITED/ACTIVE/SUSPENDED/DELETION_PENDING/DELETED다. 임시 로그인 시도 제한은 계정 정지와 별도다. 운영자는 회원 식별정보와 운영 상태를 보지만 비공개 문서 본문은 자동 열람하지 않는다.

초대 수락은 이메일·만료·일회성을 검증하고 개인 공간을 생성한다. 비밀번호 재설정 요청은 계정 존재 여부가 드러나지 않는 응답을 사용한다. 메일 미설정 1인 로컬 설치는 안전한 서버 CLI 복구 경로를 제공하며, 동작하지 않는 이메일 복구 버튼을 성공한 것처럼 표시하지 않는다.

운영자나 자기 계정의 마지막 복구 수단을 제거할 때 대체 수단을 확인한다. 마지막 운영자/공간 소유자 제거는 막는다. 자신의 비밀번호·이메일·MFA·API 키·전체 내보내기·영구 삭제 등에는 최근 재인증이 필요하다. 상세는 [인증·권한](../architecture/identity-and-access.md).

## 5. 홈과 기본 웹 요소

홈은 일정 중심 대시보드로 고정하지 않는다. 오늘 할일·다가오는 일정, 최근 기록, 정리 대기, 작업 중 문서, 실패한 작업을 작은 카드로 제공하고 순서를 조절할 수 있게 한다. Core를 끄면 추천 카드만 사라지고 다른 기능은 유지된다.

공통 요소: 탐색 메뉴, 모바일 drawer, 전역 검색, 빠른 기록 버튼, 필터 bar, 목록/table/card, 페이지 이동, 상세 패널, 폼·확인 대화상자, 변경 이력, 저장 상태, 인앱 알림. 공통 스타일·간격·버튼 위험도를 통일하되 모든 화면을 동일한 CRUD 템플릿으로 강제하지 않는다.

긴 표는 열 선택과 가로 스크롤을 허용하고 모바일에서는 핵심 필드 카드로 대체한다. 키보드 이동, 폼 label, 명확한 focus, 읽을 수 있는 오류, 상태를 색상만으로 표현하지 않는 기준을 적용한다. 접근성 목표는 WCAG 2.2 AA의 관련 항목이며 인증·준수 완료 주장은 실제 검사 전 하지 않는다. [W3C](https://www.w3.org/TR/WCAG22/)

## 6. 글 편집과 버전

글 관리는 위키와 발행용 문서가 공유하는 편집 기반 위에 각자의 목적을 둔다. 초안 작업본과 불변 revision을 분리한다. 자동저장 상태는 저장 중/저장됨/오프라인/충돌/실패로 표시하고 실패를 성공 toast로 숨기지 않는다.

저장은 baseVersion으로 낙관적 동시성 검사를 한다. 두 탭·두 기기에서 수정하면 나중 요청을 거부하고 비교/새 초안 복사/명시적인 재시도 선택을 제공한다. 페이지 이탈과 세션 만료 때 미저장 입력 손실을 막되 로그아웃 후 개인 본문을 공용 기기 저장소에 계속 남기는 것을 기본값으로 하지 않는다.

발행 전에는 공개 제목·본문·작성자·태그·출처·첨부·slug를 검토한다. 신규 발행, 기존 공개본 개정, 철회는 별도 명령이다. 문서 편집 권한만으로 공개하지 못한다. 예약 발행·공동 승인·실시간 공동 편집은 X다.

## 7. 데이터 관리의 사용자 의미

데이터 관리는 DB 테이블을 편집하는 관리자 화면이 아니다. 원본·위키·문서·파일의 위치와 사용처를 찾고, 가져오기/내보내기, 휴지통·복구, 중복 후보와 끊긴 출처, 용량·처리 실패를 관리하는 공간이다.

개인 Export는 자신의 콘텐츠와 관계를 이식하는 기능이다. 운영 Backup은 계정·DB·전체 첨부를 복구하기 위한 별도 운영 기능이며 일반 계정에 전체 DB dump를 다운로드시키지 않는다. 검색 index와 embedding은 재생성 가능한 파생 데이터로 표시한다. [데이터·운영](../architecture/data-and-operations.md).

## 8. 처음부터 필요한 추가 기능과 후속 기능

처음부터 필요한 추가 기능은 전역 검색, 첨부 관리, 자동저장 충돌, 휴지통, 권한별 감사, 세션 원격 해제, 백업 복원 시험, 실패 작업 재처리, 공개본·초안 분리다. 화면 개수보다 실제 입력 손실·누출·중복·장애를 줄이는 데 우선순위를 둔다.

후속 X: 공개 회원가입, 소셜 로그인/SSO, 계정 간 공동 Workspace, 실시간 협업, 문서별 ACL 편집기, 과금, 외부 캘린더 양방향 동기화, 웹 푸시, 네이티브 앱, 댓글·좋아요, 블로그 테마, 범용 자동화 빌더. 구조의 확장점만 남기고 빈 서비스나 미완성 UI를 미리 생성하지 않는다.

## 9. 기능 명세의 완료 기준

각 기능은 화면뿐 아니라 입력 검증·권한·상태 전이·실패·감사·복구·자동 테스트까지 포함해야 완료다. [웹 구조](../architecture/web-application-design.md), [인증·권한](../architecture/identity-and-access.md), [데이터·운영](../architecture/data-and-operations.md), [실행 순서](../plan/04-web-plan.md)가 세부 계약이다.
