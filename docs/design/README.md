# 화면·ERD 설계 기준 · 2026-09-22

기준 commit: `cb964a08a6f6a59a3394f8b75f71c4e373a0321c`. 현재 저장소의 기능·인증·웹·운영 설계를 화면과 관계 모델로 구체화했다. 제품 코드는 구현하지 않았다.

## 읽는 순서

1. [화면 와이어프레임·경로](wireframes.md): W01–W27, 기본/실패/모바일 동작.
2. [ERD](erd.md): 계정, 지식, 실행, 문서, 공개, 첨부, 작업의 7개 상세도.
3. [관계·제약 보완](schema-contracts.md): FK로 보장할 것과 명령/트랜잭션에서 검사할 것.
4. [검토 결과](../review/wireframe-erd-review-2026-09-22.md): 발견한 누락, 수정, 남은 검증.
5. [구현 백로그](../plan/task-index.md): 선행 계약, 작업 순서, 의존성과 완료 기준.

전달 패키지에는 클릭형 HTML(27개 화면+8개 SVG), 화면·ERD PDF, `schema.json`/DBML/데이터 사전, 재생성 스크립트와 검사 결과를 함께 제공한다. 저장소에는 읽고 변경 이력을 검토할 화면 명세와 Mermaid 원본을 둔다. 외부 디자인 서비스에 개인 자료를 업로드하지 않았다.

## 설계 규모와 범위

논리 엔터티는 66개이며 141개 FK 계약을 표현했다. 이 수는 vendor auth 계약, 작은 연결 테이블, 버전·작업 이력까지 합한 **전체 제품의 설계 수**다. 최초 migration에 전부 만들라는 뜻이 아니다. F 기반 18, P 개인 관리 33, P/D 공통 문서 기반 4, D 검토·주장 3, R 공개 8로 나누었다. 구현 시 인증 라이브러리가 제공하는 실제 테이블과 대응시키며 중복 인증 저장소를 만들지 않는다.

HTML은 합성 데이터와 화면 탐색·입력·상태 전환만 제공한다. 로그인·권한·저장·발행을 실제 수행하지 않는다. 왼쪽의 W01–W27 목록과 상단 상태 선택은 설계 도구의 탐색 장치이며 실제 비로그인 사용자에게 제품 메뉴를 노출하는 요구가 아니다. ERD는 논리 모델이며 운영 migration, RLS 정책, 상태 전이 트리거, 보안 검증을 대신하지 않는다.

## 검증 범위

Chromium에서 27개 화면을 1440px/390px로 확인한 54개 화면 검사에 본문 전체 가로 넘침과 JavaScript 오류가 없었다. 상태 선택 6종, 모달 Escape 닫기, SVG ERD 표시, 화면의 엔터티 참조를 확인했다. 관계 모델의 테이블/컬럼 존재, FK 타입, 참조 대상 고유키, 개인 참조의 Workspace 포함을 정적으로 검사했다.

실제 DB에 SQL을 적용하거나 인증·API·동시성·발행 보안을 검증하지 않았다. 브라우저 자동 검사도 접근성 인증이나 실제 사용자 사용성 검증은 아니다. 나머지는 구현 백로그의 release gate로 남긴다.
