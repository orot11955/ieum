# ADR 0014 · 판단 Core 제거와 개인 관리 우선 재설계

- 날짜: 2026-09-29 KST
- 상태: 채택 — 사용자의 Core 실효성 검토 후 재설계 지시
- 대체: ADR 0012·0013의 실행 계획과 카드 체계, ADR 0003·0004·0006의 판단 실험 방향

## 배경

Core(판단 엔진) 실효성을 검토한 결과는 다음과 같다.

- 제품에 연결된 판단은 한글 2·3-gram TF-IDF 글자 겹침 observe뿐이었다. semantic·hybrid·구조 진단·근거 묶음·개요·claim 검증은 Lab 전용이었다. 추출 파서는 `TODO:`·`일정:` 같은 접두어 문법만 인식했다.
- 품질 수치는 합성 40맥락·60질의에서 나왔고, 한 문장 맥락 가운데 top-10(25%) 안에 들면 성공으로 셌다. semantic 벡터는 실제 임베딩이 아니라 글자 token을 해시한 투영이었다. 실제 효용 증거는 없었다.
- 쓸모가 가장 큰 기능(비슷한 기록 찾기, 자연어 추출)은 범용 임베딩·LLM 호출로 만들 수 있다. 자체 엔진과 평가 체계가 필요하지 않다. 이음 고유 기능(구조 진단, 묶기·나누기)은 개인 규모에서 필요성이 가장 불확실했다.
- 백엔드는 P7까지 앞서 갔지만 업무 화면은 0개였다. 사용자 ACCEPTED 카드도 없었다.

## 결정

1. **판단 Core를 제거한다.** `packages/core`, `apps/lab-cli`, 합성 datasets, 판단 요청·실행·제안·노출·피드백, 자유 기록 추출, 구조 제안·변경·다중 후속 Context를 코드·계약·DB에서 삭제했다(migration `0021`). Context의 SUPERSEDED는 BE-08의 단일 `superseded_by_id` 불변식으로 되돌렸다.
2. **이음은 개인 관리 웹앱이다.** 기록(원문 revision·출처)·맥락·할일·일정·위키를 매일 쓸 수 있게 완성하는 것이 다음 목표다. 이미 검증된 백엔드(BE-01–11)를 그대로 쓰고 화면을 붙인다.
3. **문서 발행 계열은 동결한다.** 문서 작업실·모델 초안·첨부·발행·Delivery API(BE-16–20)는 코드와 테스트를 유지하되 계획에서 후순위로 둔다. 개인 관리가 완성된 뒤 다시 판단한다. 동결은 기능 추가와 화면 작업을 하지 않는다는 뜻이며, 깨지면 고친다.
4. **인증·권한은 기존대로 유지한다.** Owner/Operator, 초대, MFA, RLS, 분리된 DB role은 더 확장하지 않는다. 화면은 로그인·세션부터 만든다.
5. **지능 보조는 나중에, 얇게 붙인다.** 실사용에서 필요가 확인되면 PostgreSQL 검색에 임베딩 열·API 호출을 더하는 기능으로 추가한다. 자체 판단 엔진이나 별도 평가 Lab을 다시 만들지 않는다.
6. **프로세스를 가볍게 한다.** 75개 카드·backlog.json·render 스크립트·카드별 evidence 요구를 폐기한다. [마일스톤 계획](../plan/README.md)과 체크리스트, CI, 마일스톤당 짧은 검증 기록으로 대체한다. 과거 카드·검토·Core 증거는 Git 이력에 남는다.

## 유지하는 불변식

원문과 불변 revision/span 보존, 정규화가 원문을 덮어쓰지 않음, Unit의 다중 Context 연결과 primary 최대 하나, Task·Event·Document의 독립 수명, 명시적 명령만 의미를 바꾼다는 원칙, 서버·DB 권한 검사와 공간 격리, 공개본과 draft의 분리, 운영 DB·배포는 별도 허가 없이 변경하지 않는다는 원칙은 유지한다. Paper/Dark 디자인 계약도 유지한다.

## 결과와 한계

- context membership 무효화 job(`context_profile_invalidation`)은 BE-06 outbox·worker 검증 예시로 남아 있다. 다음 실제 job 소비자가 생기면 교체하고 제거한다.
- 운영 DB에는 `0019`–`0021`을 적용한 적이 없다. `0021`은 판단·구조 테이블을 삭제하므로, 적용 대상 DB가 생기면 inventory와 backup을 먼저 확인해야 한다.
- BE-21 개인 데이터 이식은 일부 도메인만 구현된 채 중단 상태다. 이식 범위와 archive 버전 호환은 실사용 전 백업 마일스톤에서 다시 정한다.
