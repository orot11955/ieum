# BE-05 · 업무 명령·멱등성·충돌·감사

상태: **IMPLEMENTED** (2026-09-24 KST). 선행 BE-04와 BASE-03은 VERIFIED다. Node 24.18.0/macOS에서 격리 Colima의 PostgreSQL 18.4와 HTTP 통합 시나리오를 검증했다. Linux GitHub Actions 결과는 아직 확인 전이다. 운영 DB·배포는 변경하지 않았다.

## 구현과 계약

- `business` migration 0002에 기존 사용자 설정 `version=1`, command receipt, append-only audit, outbox를 추가했다. 신규 테이블은 `ieum_migrator` 소유, 애플리케이션 role의 `SELECT, INSERT`와 공간별 `FORCE RLS`를 사용한다.
- `CommandCoordinator`는 활성 사용자/개인 공간 Owner 권한을 확인하고 잠근 뒤 같은 key의 요청을 직렬화한다. key 범위는 workspace·actor·command kind·idempotency key이며 canonical payload SHA-256이 다르면 409다. 같은 payload 재전송은 저장된 response와 command ID를 반환한다. 효과·receipt·감사·outbox는 하나의 transaction으로 commit된다. PostgreSQL deadlock/serialization 실패는 전체 transaction을 다시 시도한다.
- 첫 업무 command는 개인 설정의 시간대 변경이다. `/api/v1/me`가 `preferences.version`을 반환하고 `PATCH /api/v1/me/preferences`는 `Idempotency-Key`와 `baseVersion`을 요구한다. 오래된 version은 409와 현재 version으로 응답한다. outbox 저장 계약은 구현했으며 전달/worker는 BE-06 범위다.
- command callback은 DB 작업만 수행하도록 계약을 고정했다. 외부 모델/메일/네트워크 호출을 transaction 안에서 실행하지 않았다. 계정 생성·정지 등 BE-04 보안 수명 명령은 별도 계정 사건 경로를 유지한다.

## 미검증·데이터 영향·복구

합성 계정과 격리 Testcontainers DB만 변경했다. 운영 DB, 기존 실제 계정, 외부 네트워크 부작용, 메일, 브라우저는 미접근이다. 실제 저장 데이터의 기존 `user_preference` row에 `version=1`을 채우는 migration은 SQL 정합성과 새 DB 적용으로 검증했으며 운영 데이터 분포에서는 아직 시험하지 않았다. command audit/outbox는 workspace 삭제 시 FK cascade를 따르므로 삭제·보존 정책은 BE-22에서 재검토해야 한다.

운영 적용에는 DB/role inventory, backup, auth→role→business migration rehearsal과 별도 승인이 필요하다. 이전 API로 롤백하면 설정 version을 증가시키지 않으므로 BE-05 클라이언트와 혼용하지 않는다. schema 삭제나 DB 복원을 자동 롤백으로 취급하지 않는다.
