# BE-18 · 비공개 첨부·안전 검증·공개 파생물

상태: **IMPLEMENTED**, Linux CI 확인 후 VERIFIED로 갱신한다. 선행 BE-05·BE-11·BE-06은 VERIFIED다. 2026-09-25 KST, Node 24.18.0/macOS와 격리 Testcontainers PostgreSQL 18.4의 합성 파일로 검증했다. 운영 DB·배포·실제 사용자 파일은 건드리지 않았다.

## 계약과 구현

- `0015`는 private `asset`, 공개 후보 `public_asset`, 문서 draft 첨부 목록, 불변 revision 첨부 manifest를 추가한다. 기존 row 변환·삭제 없이 workspace FK와 FORCE RLS를 적용한다. 원본/파생본은 서로 다른 로컬 volume에 UUID 키로 저장하며 사용자 파일명은 저장 경로에 쓰지 않는다. 두 volume의 절대 경로를 함께 설정하지 않으면 첨부 생성·읽기만 비활성화된다.
- API는 JSON metadata로 PENDING을 만든 뒤 최대 20 MiB octet stream을 업로드한다. 선언 MIME·확장자·signature/실제 decoder·길이·이미지 2천만 pixel을 검사한다. 텍스트는 UTF-8과 script/iframe/svg/object/embed/html 태그를 검사하고 공개 후보를 `text/plain`으로 고정한다. PNG/JPEG/WebP는 회전·PNG 재인코딩으로 EXIF 등 metadata를 제거한다. 실패는 REJECTED 코드로 남기고 검증 전 문서 사용을 거절한다. PDF·SVG·HTML·실행 파일·archive는 허용하지 않는다.
- 다운로드와 미리보기 모두 활성 OWNER 세션 및 workspace 검사를 거치고 보관 파일의 SHA-256을 다시 확인한다. 원본은 attachment, 파생본은 inline이며 no-store/nosniff/CSP sandbox 응답이다. 별도 익명 파일 URL은 없다. 문서 첨부 목록 변경은 draft version을 올리고, 문서 revision은 asset ID와 원본·파생본 hash를 고정한다. 사용 중 asset 삭제는 거절한다.
- 문서/첨부 명령은 CommandCoordinator의 idempotency receipt·감사를 남긴다. 검증 파일의 storage 기록은 DB 명령 밖에서 수행한다. 명령 실패 시 즉시 정리하지만 프로세스가 저장 직후 중단되면 참조되지 않는 파일이 남을 수 있어 BE-23의 inventory/cleanup 대상이다. 현재 삭제 API는 사용 중 자료를 지우지 않고 논리 상태를 DELETED로 변경한다.
- 옛 아키텍처 문서의 PDF 초기 허용안과 BE-18 카드의 텍스트·검증 가능한 이미지 범위 충돌은 우선순위에 따라 후자를 적용하고 문서를 갱신했다. `public_asset`은 BE-19 승인 발행의 입력 후보이며 현재는 OWNER 전용 미리보기다.

## 미검증·배포/복구

실제 운영 volume 권한·용량, 악성코드 외부 scanner, 실제 사용자 파일 품질, 공개 사이트 노출·철회는 검증하지 않았다. 파생본이 승인 가능한지는 BE-19 검토가 결정한다. 배포 시 `0014` 뒤 `0015`를 관리자 credential로 적용하고 webroot 밖의 접근 제한된 두 volume과 백업을 준비한 다음 API를 갱신한다. 되돌릴 때 DB·파일을 보존한다. 운영 DB migration·배포·실제 파일 삭제/복원은 별도 승인 범위다.
