# BE-01 · NestJS/Fastify와 composition root

상태: **IMPLEMENTED** (2026-09-23 KST, 로컬 검증 통과; Linux CI 확인 전). 대상 카드의 선행 BASE-02는 VERIFIED였다. API·화면 재점검은 [별도 검토](../review/api-wireframe-server-entry-2026-09-23.md)에 기록했다.

## 구현 경계

- `packages/backend`의 `GetLiveness`는 Nest·HTTP·DB에 의존하지 않는다. `apps/api`의 `SystemModule`과 `apps/worker`의 application context가 같은 use case를 조립한다. worker는 self-check만 실행하며 job consumer는 BE-06 범위다.
- API는 `GET /health/live`의 `{ "status": "ok" }`만 제공한다. 입력 query는 비어 있어야 하며 422 문제 응답을 반환한다. 관리·인증·Delivery 라우트는 아직 없다.
- FastifyAdapter에 서버 생성 request ID와 `@fastify/helmet`을 적용한다. Nest global filter는 `application/problem+json`으로 오류를 반환하고 예상치 못한 예외의 문자열을 응답에 싣지 않는다. guard는 격리된 Nest/Fastify 통합 테스트에서 거부 경로를 확인했다. 실제 계정 권한 guard는 BE-02/BE-04에서 구현한다.
- API main은 Node ESM 빌드 산출물을 실행하고 Nest shutdown hook을 켠다. worker self-check는 application context를 열고 닫는다. Nest 12.0.3 / Fastify 5.12.4 / `@fastify/helmet` 13.1.1을 고정했다. 신규 릴리스 출시 대기 예외는 남기지 않았다.
