# BE-17 · 선택적 모델 정제 adapter·비용·실패 격리

상태: **IMPLEMENTED**. 기능 commit `c860e76`·`39480ec`. 선행 BE-16·BE-06·CORE-15는 VERIFIED다. 2026-09-25 KST, Node 24.18.0/macOS와 격리 Testcontainers PostgreSQL 18.4의 합성 자료로 검증했다. 운영 DB·배포·실제 사용자 문서·실제 모델 API는 건드리지 않았다. Linux CI 확인 뒤 VERIFIED로 올린다.

## 계약과 구현

- 모델 사용은 기본 off다. 활성 개인 OWNER가 설정 version을 잠가 `externalModelEnabled`를 켜고, 개별 요청에서 `consent:true`를 제출해야 한다. API는 문서·현재 draft version·특정 evidence pack revision·선택한 source index와 target block을 검사한다. 모델을 쓰지 않는 pack/문서 명령은 독립이다.
- `0014`는 생성 요청, 불변 artifact, 명시 적용 이력 세 테이블을 더한다. 기존 row 변환/삭제가 없고 workspace FK, FORCE RLS, 제한된 application role 권한을 둔다. 요청·취소·적용은 CommandCoordinator의 원자적 감사/receipt를 남긴다. `generation.requested`는 outbox relay가 `generation-run`으로 옮기고 자동 재시도 0회, job 만료 180초다.
- worker는 전송 전 활성 OWNER·opt-in·draft version·선택 출처의 fresh 상태·입력 hash·model/prompt revision·token/비용 한도를 재검사하고 DB 트랜잭션 밖에서 호출한다. 호출 중 취소와 동의 철회를 polling/AbortSignal로 감지하며, 결과 저장 전 다시 검사한다. 프로세스 중단 후 5분 넘은 RUNNING은 주기적으로 `WORKER_INTERRUPTED`로 종료한다. 실패는 고정 코드만 저장한다.
- 허용 provider는 OpenAI Responses의 고정 HTTPS endpoint 하나다. worker credential만 사용하고 `store:false`, `tools:[]`, `tool_choice:none`, JSON schema 출력, 응답 1MB 제한을 적용한다. 프롬프트 입력은 선택한 source index/text와 문서 plain text/대상 block text뿐이다. 출처 안의 지시는 데이터로 취급하라는 상위 지시를 별도로 전송한다. DB·파일·임의 URL·tool 접근은 provider에 전달하지 않는다. `store:false`는 provider의 모든 처리/보존을 없앤다는 의미가 아니다.
- provider 출력을 엄격한 schema, 선택한 출처 index, 요청한 target block, token/비용 한도로 검사한다. 초안은 즉시 바꾸지 않는다. proposal/diff/source snapshot을 artifact로 저장하고, 사용자가 선택한 proposal ID를 별도 apply 명령으로 적용한다. apply는 현재 draft version과 원본 출처 pointer를 잠가 fresh 여부를 다시 검사하며, 적용 block을 재검토 대상으로 반환한다. 생성 텍스트의 사실성은 자동 승인되지 않는다.
- 비용은 operator가 설정한 모델별 input/output 단가와 provider usage로 계산한 추정치다. 전송 전 UTF-8 byte 기반 보수적 입력 token 상한과 provider output token cap으로 요청/서버 예산을 제한한다. 실제 청구 금액의 일치를 보증하지 않는다.

## 미검증·배포/복구

실제 provider 계정·요금·모델 응답, 실제 사용자 텍스트 품질, 브라우저의 모델 동의 UI는 검증하지 않았다. 운영 credential이나 사용자 자료가 없어 실제 외부 전송을 하지 않았다. 운영 반영은 `0013` 뒤 별도 관리자 credential로 `0014`와 pg-boss `generation-run` queue를 준비하고 worker/API 설정을 일치시킨 뒤 진행해야 한다. 운영 DB migration·배포는 별도 승인 범위다. 앱을 되돌릴 때 신규 private artifact를 보존하며, 실제 데이터를 지우는 down migration은 제공하지 않는다.
