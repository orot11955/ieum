## 1.1 기록 (보존)

### 현재 판단

CORE-01–15의 로컬/Linux 단위·계약 검증은 **Core 계산/검증 계약**의 증거다. 합성 B0/B1/B2/B3 결과를 실제 관련성, 구조 변경 효용, 문서 정제 효용 또는 제품 추천 승인률로 환산하지 않았다. 현재 제안 정책은 validation 목표를 통과한 실제 설정이 없으므로 observe에 머문다. 구조 변경은 preview 계약만, 모델 초안은 출처/claim 검증 계약만 있으며 실제 적용·사용자 검토 경로는 없다. CORE-16의 `core-quality-report.md`와 활성화 가능 정책 목록은 산출하지 않았다.

### 당시 재개 조건

1. FE-14와 FE-16, 해당 BE·QA 선행 카드가 VERIFIED/ACCEPTED되고 실제 사용 흐름에서 시간·수정량·피로도를 기록할 수 있어야 한다.
2. 사용자가 평가용 실제 기록 사용 범위를 허용하고, 저장소 밖 private dataset에 원본 계열·시점·권한·검토 라벨을 갖춘 development/validation/새 holdout을 준비해야 한다. 초기 50–100개 기록의 라벨 비용을 확인한 뒤 계획의 100–300개 확장 여부를 결정한다.
3. 관련성, 구조 변경, 글 정제별 분모·slice·불확실성·실패 사례와 직접 검색/수동 정리 대비 사용자 시간을 각각 측정한다. 추천 0건, 미검토 pair, 같은 과제 기억 효과와 중복 origin을 별도로 보고한다.
4. 실제 결과와 G5/G6 검토를 확인한 뒤에만 CORE-16을 IMPLEMENTED/VERIFIED로 전환하고 활성화 가능 정책을 판정한다.
