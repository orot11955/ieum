# M1 · 앱 기반과 로그인

상태: **구현·로컬·원격 Linux CI 검증 완료. 사용자 인수는 아직.** 원격 run `36524554535`(commit `777c017`)는 4개 job 모두 성공했다. 실제 운영 DB·배포·사용자 자료는 다루지 않았다.

## 범위

React Router 8.4.0 기반 앱 shell, 인증 bootstrap, 로그인(W01)·2단계 인증 확인(W03)·초대 수락(W02), 홈, 설정(테마·로그인된 기기·2단계 인증), 운영자 초대, 404·권한 없음·오류 route. 서버 상태는 TanStack Query, 폼은 React Hook Form + Zod, 편집 중 값은 각 feature 안에 둔다. 디자인 갤러리와 편집기 spike는 `/dev/gallery`로 옮겼고 개발 빌드에서만 열린다.

## 설계 결정

- 캐시 key는 사용자 id로 시작한다(`["user", id, …]`). 계정이 바뀌면 이전 계정의 캐시가 화면에 나올 수 없고, 로그인·로그아웃·만료 시 `queryClient.clear()`로 전부 지운다. 본문 영역은 사용자 id를 `key`로 다시 만든다.
- 401 응답은 세션 만료 이벤트로 로그인 화면 이동과 캐시 삭제를 일으킨다. 로그인·2단계·비밀번호 확인처럼 401이 "값이 틀림"을 뜻하는 요청은 `sessionBound: false`로 제외한다.
- 서버의 유휴 만료를 위해 사용자 입력이 있을 때 5분에 한 번 `POST /api/v1/me/activity`를 보낸다.
- 초대 토큰은 URL fragment로만 전달해 요청줄·Referer·서버 로그에 남지 않는다. 수락 후 fragment를 지운다.
- 복귀 경로는 같은 앱의 상대 경로만 허용한다(`//`·`/login` 거부).
- Vite dev server가 `/api`를 API로 프록시해 브라우저가 한 origin만 본다. API의 Host/Origin 검사를 약화하지 않았다.

## 실제 실행 (Node 24.18.0, macOS, Colima PostgreSQL 18.4)

| 명령 | exit | 결과 |
|---|---:|---|
| `npm run prep:check` | 0 | 문서 링크·디자인 검사 |
| `pnpm contracts:check`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck` | 0 | |
| `pnpm test:unit`, `pnpm build`, `pnpm api:smoke` | 0 | |
| `pnpm test:web` (`DOCKER_HOST`는 Colima 프로필 소켓) | 0 | Playwright 16개 통과: 기존 갤러리·편집기 8개 + M1 시나리오 8개 |

M1 시나리오는 격리 PostgreSQL 컨테이너(`apps/api/scripts/e2e-stack.mjs`가 migration·DB role·운영자 계정·API를 준비)에서 실제 API로 실행한다: 보호 URL→로그인→복귀와 새로고침, 잘못된 비밀번호, 로그아웃 후 뒤로가기(계정 정보가 DOM에 한 번도 나타나지 않음), 초대→두 번째 계정 생성·운영자 화면 접근 거부·사용한 초대 재사용 거부, 같은 브라우저 계정 전환(새 계정이 처음 보인 프레임부터 이전 계정 이메일이 나타나지 않음), 다른 기기에서 세션을 끝냈을 때 만료 안내, 2단계 인증 등록·틀린 코드·백업 코드 1회 사용, 320px 좁은 화면·다크 테마·본문 건너뛰기.

Docker 소켓이 잘못 잡힌 첫 실행에서는 web server가 180초 뒤 timeout이었다. 소켓을 지정해 통과했고 코드 문제가 아니었다.

## 미검증·제한

- 자동 IME 조합 입력, 강제 색상 모드, 스크린리더 실제 읽기는 검증하지 않았다(갤러리의 forced-colors 검사만 유지).
- 비밀번호 재설정·복구(W03의 복구 부분)와 계정 정지 화면은 구현하지 않았다. 복구는 서버 CLI(`recover`)로만 가능하다.
- 초대 링크는 화면에 표시만 한다. 메일 발송은 없다.
- 사용자 ACCEPTED 없음.
