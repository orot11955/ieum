## 구현과 계약

- `business.calendar_event` 신규 테이블에 `TIMED`와 `ALL_DAY`를 DB CHECK로 분리했다. 시간 지정은 IANA 시간대, 입력한 local 시각·offset, UTC 시작/끝 instant를 보존한다. 종일은 시작 date와 exclusive 종료 date를 그대로 보존한다. state는 CONFIRMED/CANCELED이며 optimistic version, command receipt·감사를 쓴다.
- local 시각은 저장 전에 IANA 시간대의 실제 UTC 후보로 역변환한다. DST gap은 거절하고 fold는 명시적 UTC offset이 있어야 확정한다. end<=start, 유효하지 않은 달력 날짜·시간대, offset 불일치는 422다. 모델 후보의 시간대 없는 입력은 API 계약에서 거절한다. 반복·동기화·자연어 자동 등록은 이 카드 범위 밖이다.
- 기간 조회는 요청자의 조회 시간대로 날짜 범위를 UTC instant로 변환한다. 시간 지정 일정은 UTC `[start,end)` 겹침, 종일 일정은 date `[start,end)` 겹침으로 필터링한다. 조회 시각의 local 표시와 겹치는 일정 ID를 반환한다. 최대 366일·500건을 넘으면 422로 명시적으로 거절해 결과를 조용히 자르지 않는다. 취소 일정은 기본 목록에서 제외하되 `includeCanceled=true`로 조회할 수 있다.
- Nest HTTP의 생성·상세·기간 목록·편집·상태 전이는 Zod/OpenAPI와 연결했다. GET은 `Cache-Control: no-store`; 변경은 같은 Origin·활성 세션·개인 공간 OWNER 검사를 거친다. DB는 FORCE RLS·WITH CHECK, 필요한 열에만 UPDATE 권한을 준다.
