# BE-16 · 자료 묶음·출처 고정·문서 작업실

상태: **IMPLEMENTED, Linux CI 검증 대기**. 선행 BE-11·BE-07·BE-08·CORE-14는 VERIFIED다. 2026-09-25 KST에 Node 24.18.0/macOS와 격리 Testcontainers PostgreSQL 18.4의 합성 자료만 사용했다. 운영 DB·배포·실제 사용자 문서는 변경하지 않았다.

## 구현·계약

- `0013`은 외부 발췌 identity/불변 revision, 문서별 evidence pack identity/불변 revision, 문서 작업실 pointer/불변 revision 여섯 테이블을 추가한다. workspace composite FK, FORCE RLS, application role의 revision SELECT/INSERT 전용 grant와 root 제한 UPDATE를 적용한다. 기존 데이터를 변환하거나 삭제하지 않는다.
- 외부 발췌는 사용자가 입력한 HTTP(S) URL·저자·발행일·텍스트를 보관하며 URL fetch를 하지 않는다. 개정은 새 revision, 삭제 명령은 `DELETED` 상태를 만든다. 과거 private pack snapshot의 텍스트는 유지하고 live source state는 unresolved가 된다. 실제 사용자 삭제·purge 정책은 BE-22 범위다.
- 자료 묶음은 capture revision, Unit, document revision, Task result, 외부 발췌의 정확한 workspace·현재 revision·선택적 UTF-16 span을 확인한다. manifest에는 선택 당시 텍스트·원본 hash·originKey·외부 메타데이터를 고정한다. 조회 시 현재 출처의 revision/상태를 비교해 `fresh`·`stale`·`unresolved`를 산출한다. 같은 원본의 복수 인용은 origin family 하나로 세며 독립 근거로 중복 집계하지 않는다. Core-14의 Unit 전용 계산 입력과 달리 이 이종 출처 검증·영속화는 backend application 경계에서 처리하고, 문서 목적 체크리스트는 Core-14 정본을 재사용한다.
- 작업실은 현재 draft version과 특정 pack revision을 잠가 목적·독자·outline의 역할/인용·충돌·claim mapping·문서별 source manifest snapshot을 불변 revision으로 저장한다. 존재하지 않는 source index, 변경된 block 평문/전체 block hash, source 없는 인용/출처 있는 author-added, 정확하지 않은 quote를 거부한다. 조회는 draft block hash 변화의 `needs_remap`과 출처 stale/unresolved를 반환한다. `readiness`는 누락 자료·수동 검토 안내이며 사실성/발행 승인이 아니다. `claim.textHash`와 `claim.blockHash` 규칙은 [편집 계약](../plan/editor-schema.md)에 적었다.
- API 경로는 `/api/v1/workspaces/{wid}/external-excerpts`, `/documents/{id}/evidence-packs`, `/documents/{id}/workbench` 아래에 있다. 기존 세션·Host/Origin·활성 OWNER, CommandCoordinator의 transaction·idempotency receipt·audit를 사용한다. 문서 본문의 `external_excerpt` sourceReference도 workspace·불변 revision·hash·span을 검증한다.

최초 HTTP 실행의 pack 조회 422는 PostgreSQL `date`가 런타임 `Date`로 반환되는 문제였고, SQL `published_at::text`로 API/manifest 날짜를 원래 YYYY-MM-DD로 고정했다. 다음 실행의 발췌 개정 422는 `baseVersion`을 strict 발췌 본문에 포함한 오류였고, API에서 버전 필드를 분리했다. 두 수정 뒤 같은 통합 시나리오가 통과했다. 보안 경계 읽기 전용 검토는 인증·workspace·외부 입력·RLS에서 확인된 결함을 찾지 못했으며 테스트를 대신하지 않는다.

독립 `change-review`에서 source reference의 ID/revision만 바꾸고 label을 유지하면 평문 hash만으로 재검토를 놓친다는 회귀를 확인했다. 전체 block의 정규화 hash를 추가하고 동일 label 출처 교체 HTTP 반례로 수정·통과했다.

## 한계·배포/복구

현재 통합 시험은 서버 HTTP·격리 DB의 합성 자료다. FE-09 이후의 실제 문서 작업실 UI, 브라우저 IME/충돌/상태 표시, 실제 자료의 출처 품질과 수동 인용 검토는 확인하지 않았다. BE-16의 `DELETED`는 논리 삭제이며 과거 pack snapshot을 지우지 않는다. 모델 정제·공개 발행·Delivery는 BE-17 이후 카드다.

`0013`은 관리자 migration credential로 `0012` 뒤 API 코드보다 먼저 적용해야 한다. 이전 API로 되돌릴 때 신규 테이블을 보존한다. 실제 데이터가 생긴 뒤 테이블 제거는 데이터 손실이므로 제공하지 않으며, 운영 복구·삭제는 inventory·backup·별도 사용자 허가가 필요하다.
