# BE-11 · 위키·문서 공통 draft/revision 엔진

상태: **IMPLEMENTED**, Linux GitHub Actions 결과 대기. 선행 BE-05·FE-02는 VERIFIED다. 2026-09-25 KST에 Node 24.18.0/macOS와 격리 Testcontainers PostgreSQL 18.4에서 합성 자료로 검증했다. 운영 DB·배포·실제 사용자 문서는 변경하지 않았다.

## 구현·계약

- Wiki/Article/Note는 같은 `document` identity와 `document_draft`, `document_revision` 엔진을 사용한다. draft는 `baseVersion`이 일치할 때만 업데이트하며 `saveSequence`를 응답에 돌려준다. 같은 키 재시도는 receipt를 반환하고 다른 payload의 키 재사용은 409다. 두 탭이 같은 버전을 보내면 한 저장만 성공하고 다른 저장은 현재 버전을 포함한 409를 받는다.
- seal은 정확한 draft version의 JSON을 별도 불변 revision으로 봉인한다. restore는 선택한 옛 revision의 본문/제목을 **새 revision**으로 복사하며 열려 있는 현재 draft를 바꾸지 않는다. revision table은 application DB role에 UPDATE/DELETE 권한을 주지 않는다. draft 저장 응답의 `recheckBlockIds`/`removedBlockIds`는 변경된 주장 재검토 대상이지 사실성 점수가 아니다.
- 위키 링크는 별도 명령으로 같은 workspace의 활성 WIKI ID만 받는다. link set은 `baseLinkVersion`으로 충돌을 감지하고 삭제 뒤 역링크 조회에서도 사라진다. 본문에 범용 polymorphic link를 넣지 않았다.
- 저장 본문은 FE-02 `schemaVersion:1`의 허용 node/block ID 스키마를 사용한다. NUL·짝 없는 UTF-16 surrogate·알 수 없는 node/version을 거부한다. `unit` 출처는 정확한 workspace·revision·originKey·본문 SHA-256·선택적 UTF-16 span을 검증한다. `document_revision` 출처는 정확한 revision과 정규화 JSON SHA-256 및 [파생 평문 span 규칙](../plan/editor-schema.md)을 검증한다. 아직 영속 검증 구조가 없는 `external_excerpt`는 저장하지 않는다. 출처가 존재한다는 사실은 claim의 진실성 승인이 아니다.
- `0012`는 기존 데이터 변환 없이 네 테이블과 composite workspace FK, FORCE RLS, 제한된 application grant를 추가한다. API는 기존 세션/Host/Origin·활성 OWNER 확인과 CommandCoordinator의 transaction·receipt·audit를 사용한다. 신규 경로는 `/api/v1/workspaces/{wid}/documents` 아래 생성·목록·상세·draft PUT·revision 봉인/조회/복원·링크 PUT이다.

## 한계·배포/복구

BE-11은 서버의 버전 직렬화와 ACK 식별 정보까지만 제공한다. 실제 위키 화면에서 네트워크 ACK가 역순으로 도착했을 때 미저장 draft·공통 기준·서버본을 보존하는 UI와 실제 한글 IME/재시작 E2E는 [FE-09·FE-10·QA-04](../plan/09-implementation-sequence.md)의 후속 검증이다. 현재 HTTP 테스트의 역순 반례는 오래된 요청을 새 요청 뒤에 보내 409를 확인한 것으로 실제 응답 전달 순서를 인위적으로 역전시킨 시험은 아니다. 출처/문서 평문은 합성 데이터이며 실제 근거 품질·공개 안전 검토와 운영 부하를 뜻하지 않는다.

`0012`는 API 코드보다 먼저 관리자 migration credential로 적용하고 owner/grant/RLS를 점검한다. 이전 API로 돌아갈 때 신규 테이블은 남겨 새 문서를 보존한다. 문서가 기록된 뒤 테이블을 제거하는 down migration은 데이터 손실이므로 제공하지 않는다. 운영 schema 복구는 inventory·backup·별도 사용자 허가를 거쳐야 한다.
