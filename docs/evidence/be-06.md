## 구현과 계약

- `context.membership.changed`를 첫 실제 비동기 사건으로 연결했다. 기존 명령 transaction이 원본 변경·감사·receipt·outbox를 함께 저장한다. relay는 전역 outbox를 찾아 pg-boss job과 `command_dispatch` receipt를 **같은 DB transaction**에 기록한다. 지원하지 않는 미래 event는 임의로 소비하지 않는다.
- worker의 queue 연결은 별도 `ieum_job_relay`, 업무 효과는 `ieum_application` 로그인으로 수행한다. 두 역할의 겸용·관리자·owner·auth 권한은 시작 검사에서 거부한다. queue에는 outbox/workspace ID만 두고, 처리 시 receipt actor·활성 OWNER·해당 workspace·현재 Context를 다시 확인한다. 원문은 queue에 싣지 않는다.
- 처리 결과는 Context membership revision의 단조 증가 무효화 watermark다. 중복·늦은 job이 revision을 낮추거나 제안을 중복 생성하지 않는다. pg-boss는 재시도 3회와 lease 만료를 관리하며, 상태 조회는 현재 권한을 확인한 뒤 QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELED/UNKNOWN과 retry count만 반환한다. 이것은 BE-12 profile 재생성의 입력이며 profile 생성 자체는 BE-12에서 구현한다.
- 운영 준비 순서는 별도 관리자 credential로 business migration과 pg-boss schema 설치·queue 생성·`queue-grants.sql`을 적용하고, 두 runtime URL을 서로 다른 최소 권한 login으로 발급한 뒤 worker를 시작하는 것이다. 운영 적용은 이번 카드에 포함되지 않는다.

## 한계·데이터 영향·복구

합성 계정과 격리 DB만 변경했다. 실제 사용자 자료, 운영 queue·배포·backup/restore는 미검증이다. queue 전달·재시도는 외부 모델/메일의 exactly-once 효과를 뜻하지 않는다. 취소와 거의 동시에 완료되는 업무 효과는 작업별 transaction·revision 검사가 필요하다. 현재 worker의 효과는 무효화 watermark 하나이고, 실제 profile/제안 생성 및 취소 UI는 후속 카드에 속한다. 운영 적용에는 기존 role/schema inventory·backup·migration rehearsal·서비스 배포 순서·별도 허가가 필요하다. 0007은 추가형 migration이며 파괴적 down migration을 제공하지 않는다.
