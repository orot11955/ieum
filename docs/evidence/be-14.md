## 구현과 계약

- 현재 허용된 adapter는 네트워크 호출이 없는 `LocalExtractionParser`다. 기록의 `TODO:`/`할 일:`/미완료 체크박스, 날짜를 적은 `EVENT:`/`일정:`, `NOTE:`/`생각:` 줄에서 후보를 만든다. 일반 문장 전체의 의미를 추출하는 모델 provider는 연결하지 않았다. 인식하지 못한 문장은 후보가 0개이며 원문 저장을 막지 않는다.
- 파서는 현재 OWNER 권한으로 읽은 Capture revision만 받으며 DB transaction 밖에서 실행한다. Core가 UTF-16 source span·원문 일치·revision·시간 표현·stable fingerprint를 확인한다. 파서 timeout/invalid JSON은 503 `EXTRACTION_PARSER_UNAVAILABLE`이고 원문 저장·기존 Task/Event 조작과 분리된다.
- 새 `0010` 추가형 migration은 source revision과 후보 payload·decision key·상태·승인 대상 참조를 보관한다. 후보는 조회와 승인 전까지 업무 항목을 만들지 않는다. 미리보기는 원문 개정 여부, 동일 source의 기존 대상, 제한된 제목 유사도 경고와 Task의 현재 상태를 보여준다. 제목 유사도 경고는 중복 판정이나 의미 정확도 보장이 아니다.
- 수락은 현재 Capture revision과 사용자가 본 revision, 원문 출처, 이미 승인된 동일 fingerprint를 재검사한다. 사용자가 편집한 제목·본문·시간대·일정만 shared Task/Calendar 검증 경계로 전달한다. 원문 span을 가리키는 Unit과 Task/Event/Unit 대상, 후보 상태, 명령 receipt·감사·outbox를 한 transaction에 저장한다. 완료된 기존 Task는 유지하고 동일 source의 재생성을 거부한다. 일정의 미확정 시간대는 명시적 schedule 확인이 필요하다. 거절은 대상 생성 없이 상태·receipt·감사만 남긴다.
- `extraction.accepted` outbox는 영속 기록이며 현재 relay/worker의 dispatch 대상은 아니다. 운영 반영은 관리자 credential로 `0010`을 적용하고 application role의 grant/RLS를 확인한 뒤 API를 배포한다. 운영 DB 적용은 별도 승인·inventory·backup·rehearsal이 필요하다.
