# BE-15 · 구조 변경의 원자적 적용과 역변경

상태: **IMPLEMENTED**. 선행 BE-13·BE-08·CORE-13은 VERIFIED. 2026-09-24 KST에 Node 24.18.0/macOS와 격리 Docker PostgreSQL 18.4에서 검사했다. 운영 DB·배포·실제 사용자 자료는 다루지 않았다.

## 계약과 구현

- 명시적 사용자 요청으로 SPLIT, MERGE, LINK, CREATE_PARENT preview를 만든다. 새 Context 정의·원본 Unit의 모든 소속 변경·관계 변경을 승인 전 화면에 반환한다. 이 경로는 수동 mapping이며 CORE-13의 vector 진단/제안 품질을 서버에서 재계산하거나 추정하지 않는다.
- preview는 OWNER의 현재 공간에서 source 전체 Unit, 각 Unit revision·membership version·before/after, Context identity·membership revision, 활성 관계 그래프 hash, 충돌·부모 순환·선택적 primary를 검사하고 1시간 유효한 proposal과 서명을 보존한다. accept는 제안 작성자와 서명을 확인하고 전체 전제를 안정된 잠금 순서에서 다시 검사한다. stale은 409이며 부분 적용이 없다.
- `0011`은 구조 제안·변경 로그·복수 후속 Context 이력을 추가한다. 원본에 소속이 남은 SPLIT은 ACTIVE, 완전 SPLIT과 MERGE는 SUPERSEDED다. 단일 후속은 기존 `supersededById`를 함께 채우고, 복수 후속은 lineage 행으로 조회한다. deferred DB trigger는 후속 이력 없는 `SUPERSEDED`+null을 거부한다.
- 승인 transaction에 새 Context/revision, Unit 소속 이력과 version, 관계, 원본 state/revision, lineage, mutation before/after, receipt·audit·outbox를 함께 기록한다. 소속 변화는 기존 `context.membership.changed` outbox로 profile watermark 작업에 연결된다. `structure.applied`·`structure.undone` outbox는 현재 relay dispatch 대상이 아닌 영속 기록이다.
- undo-preview는 당시 변경한 Unit·관계·후속 이력·원본 상태를 재검사한다. undo는 touched 소속/관계만 역적용하며 새로 추가된 Unit이나 생성된 Context를 삭제·보관하지 않는다. 이후 touched Unit 변경 또는 원본 identity 변경은 409로 멈추고 새 inverse 검토가 필요하다. 과거 Context identity revision 조회는 DB timestamp 정밀도로 당시 membership·relation·successor를 조회한다.
- API는 `/api/v1/workspaces/{wid}/structures/...` 아래 preview/accept/undo-preview/undo를 제공한다. 기존 세션·Host·Origin·활성 OWNER 검사와 문제 응답을 사용한다. API 전에 `0011`을 적용하고 grant/FORCE RLS를 확인해야 한다.

## 한계·데이터 영향·복구

합성 fixture와 격리 DB만 변경했다. CORE-13 진단을 위한 실제 vector·독립 원본 신호는 연결하지 않았으므로 수동 mapping의 적합도나 구조 제안 품질은 검증하지 않았다. 기존 문서/발행본의 source 참조 자체를 재작성하지 않고 불변 Context revision과 후속 이력으로 추적한다. 브라우저 UI·실제 사용자 데이터·운영 migration/부하·배포는 미검증이다. `0011`은 신규 테이블과 기존 Context 제약 변경을 포함하며 파괴적 down migration은 제공하지 않는다. 문제가 생기면 이전 API 코드를 배포하고 새 이력 테이블을 보존해 조사한다. 운영 schema 복구는 사전 inventory·backup·별도 허가가 필요하다.
