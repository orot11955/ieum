# FE-02 · 편집기·폼·HTTP 계약 spike

상태: **IMPLEMENTED**. 선행 FE-01과 BASE-03은 VERIFIED. 2026-09-25 KST macOS/Node 24.18.0과 합성 브라우저·HTTP fixture로 검증했다. Linux CI 결과를 확인한 뒤 VERIFIED로 올린다.

## 구현·계약

- `EditorEnvelopeSchema`는 기존 `schemaVersion:1`을 유지하고 paragraph/heading(1–3), text/bold/italic/hardBreak/sourceReference, UUID block ID, 출처 revision/hash/UTF-16 span을 엄격히 검증한다. 중복 ID·알 수 없는 node·mark·속성을 거부한다. `compareEditorBlocks`는 변경·신규 블록의 재검토와 제거 블록을 반환한다.
- Tiptap 3.31.3의 무료 편집 코어/UniqueID로 작은 `EditorAdapter`를 만들었다. source reference는 합성 표본으로만 삽입하며, 편집 중 조합 입력의 JSON callback을 보류한다. BE-11 저장은 별도의 baseVersion·권한·출처 실재 검증이 필요하다.
- React Hook Form 7.88.0+Zod 4.6.5 폼은 미저장 제목을 소유한다. OpenAPI 생성 타입+`openapi-fetch` 0.17.0의 합성 Capture 요청을 TanStack Query 5.103.2 mutation으로 시험했다. HTTP 오류와 형식 오류는 입력을 지우지 않고 표시한다. 실제 backend 세션·저장은 연결하지 않았다.
- [편집 저장 계약](../plan/editor-schema.md)에 block ID/claim 재검토 규칙과 기존 Markdown의 변환·export 손실 범위를 고정했다. 원문 Markdown은 자동 변환하지 않는다. 동결된 token/theme/recipe/lock은 수정하지 않았다.

실제 브라우저에서 확인한 합성 편집기 화면: [390px 캡처](assets/fe-02-editor-390.png). 조합 테스트는 Chromium에 합성 CompositionEvent/`isComposing` 키 이벤트를 전달한 것으로, 실제 한글 입력기·스크린리더 실측은 아니다. 제품 빌드는 성공했으나 Tiptap을 포함한 갤러리 JS가 약 825KB로 Vite chunk 경고를 냈다. 후속 실제 화면 분리 시 route 단위 로딩을 검토한다.

읽기 전용 `security-review`는 현재 로컬 preview와 동일 출처 합성 HTTP 경계에서 확인된 취약점을 찾지 못했다. 다만 누락 label HTML의 `null` 렌더링 가능성을 지적해 안전한 표본 label과 저장 JSON 거부 반례를 추가했다. 운영 DB·배포·기존 Markdown 데이터는 변경하지 않았다. BE-11이 JSON 저장·충돌/응답 순서·revision 불변성·출처 권한 검증을 구현하기 전에는 갤러리를 실제 문서 저장 기능으로 간주하지 않는다.
