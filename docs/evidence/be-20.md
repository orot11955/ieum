# BE-20 · Delivery 전용 API·읽기 권한·클라이언트

상태: **IMPLEMENTED**. 선행 BE-19·BASE-03은 VERIFIED다. 2026-09-25 KST, Node 24.18.0/macOS와 격리 Testcontainers PostgreSQL 18.4의 합성 문서·첨부·credential로 검증했다. 운영 DB·배포·외부 블로그·실제 사용자 자료는 건드리지 않았다.

## 계약과 구현

- `0017`은 서버용 Delivery credential의 SHA-256 digest·channel·만료·폐기 상태를 추가하고, 후속 `0018`은 발급 당시 계정의 `authz_version`을 저장한다. bearer 원문은 발급·회전 응답에서 한 번만 반환하고 DB·receipt·로그에는 저장하지 않는다. 관리 API는 활성 OWNER 세션·same-origin·최근 5분 인증으로 발급·목록·회전·폐기를 처리한다. 명령의 상태 변화와 본문 없는 `identity_event`는 한 transaction에 저장한다. 계정 정지 시 이전 키는 무효이며 정지 해제 후에도 다시 유효해지지 않는다.
- `delivery-main`은 관리 API와 다른 Nest bootstrap이다. `ieum_delivery` 전용 DB login만 허용하고 업무·인증·credential 테이블 조회, 복제·관리·위험 역할 전환·모든 projection 테이블의 쓰기/비우기 권한을 시작 시 거부한다. 전용 역할은 발행된 **현재** 공개 revision·alias·asset projection만 읽는다. credential 검증 함수는 account/workspace/owner membership/channel 활성·만료·폐기를 검사하며 상태 변경과 직렬화한다.
- 외부 소비자는 DB·세션·관리 UI를 몰라도 `packages/contracts/openapi/delivery.json`의 Bearer 계약으로 목록/상세/slug alias/현재 revision/공개 asset을 읽는다. 목록은 서명된 cursor와 최대 50건, ETag·`private, no-cache, must-revalidate`를 사용한다. 304 판단 전에 매번 credential과 현재 상태를 확인한다. 철회·개정된 과거 본문/asset은 API와 Delivery 역할 RLS에서 제공하지 않는다. 공개 첨부는 파생 volume만 읽고 저장 hash·길이를 재검증한다.
- Delivery 서버에는 `DELIVERY_DATABASE_URL`, `IEUM_ASSET_DERIVATIVE_ROOT`를 설정한다. 서버용 키를 브라우저 bundle/URL에 넣지 않는다. 익명 공개 경로는 활성화하지 않았다. 이미 다운로드되거나 정적 빌드된 외부 사본의 회수는 보장하지 않는다.

## 미검증·배포/복구

실제 외부 블로그 소비자와 CDN/정적 빌드의 철회 반영 시간, 운영 volume 권한·용량, 운영 DB 권한 배치는 검증하지 않았다. HTTP 응답이 이미 시작된 뒤의 네트워크 전송은 철회 시 강제로 회수할 수 없다. 신규 요청은 철회 commit 뒤 현재 상태를 확인한다. `0016` 뒤 `0017`과 `0018`을 관리자 credential로 적용하고 전용 DB login·파생 volume을 준비한 다음 관리 API와 Delivery listener를 갱신한다. `0018` 이전에 발급한 키는 발급 시점 `authz_version`이 없어 무효화되므로 배포 후 새 키를 발급해야 한다. 되돌릴 때 credential digest·projection·발행 이력을 보존하고 Delivery listener를 닫는다. 운영 DB migration·배포·복원은 별도 승인 범위다.
