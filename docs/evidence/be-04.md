## 구현과 계약

- `business` migration 0001에 설치 singleton, 개인 workspace 접근, 운영자, 사용자 설정, 초대 digest/만료/일회 수락, 계정 사건을 추가했다. Auth vendor schema와 업무 schema, 인증/업무 DB login을 분리했다.
- 공개 signup은 비활성이고, 최초 운영자는 로컬 대화형 `pnpm --filter @ieum/api bootstrap`으로만 만든다. 비밀번호는 숨겨 입력한다. 중단 뒤 같은 이메일/비밀번호 재시도와 동시 bootstrap을 처리한다. 초대 수락은 개인 workspace를 만들며, 다른 계정의 공간은 RLS와 서버 membership 검사로 막는다.
- 관리 API의 `/api/v1/me`, 세션 목록/기기별 철회, 명시적 활동 기록, 시간대, 운영자 초대 발급·계정 정지/복귀, 초대 수락을 Zod/OpenAPI 계약으로 고정했다. 초대 토큰은 발급 응답에서 한 번만 보여주며 DB에는 SHA-256 digest만 보관한다. 메일 전송은 아직 연결하지 않았다.
- Better Auth의 로그인·로그아웃·TOTP·복구 코드를 native Fastify handler로 유지한다. 업무 API는 매 요청 세션과 계정·workspace 상태를 다시 확인한다. 세션 cookie cache를 끄고 서버에서 7일 절대·12시간 유휴 만료를 검사한다. background GET은 활동 시각을 갱신하지 않는다. FE-04는 실제 키보드/포인터 활동에만 `/api/v1/me/activity`를 호출해야 한다.
- 계정 정지는 마지막 활성 운영자를 보호하고, 기존 세션·MFA 대기 challenge·trusted-device grant를 철회한다. 전용 DB 잠금 풀에서 인증 POST와 정지를 직렬화한다. 로컬 `recover` 명령은 서버 TTY가 있어야 하며 비밀번호 변경·선택적 MFA 초기화·세션/일회용 인증 기록 철회·감사 사건을 남긴다.

## 미검증·데이터 영향·복구

합성 Testcontainers 및 로컬 격리 DB만 변경했다. 실제 운영 DB·메일·브라우저·배포는 미접근이다. 개인 원문 자료가 아직 없어 운영자에게 타인 원문이 노출되지 않는다는 최종 통합 gate는 후속 업무 엔터티와 QA-03에서 재확인해야 한다. 민감 명령의 10분 재인증, 운영자 MFA 강제, 실제 FE 활동 신호, 메일 전송은 릴리스 전 해당 카드와 통합 gate의 미완료 사항이다. 이 증거는 그 완료를 주장하지 않는다.

운영 적용에는 기존 DB/role inventory, backup, auth→role→business migration rehearsal, 분리 credential 확인과 별도 승인이 필요하다. 운영 DB migration 및 downgrade는 실행하지 않았다. 앱 롤백은 이전 바이너리로 가능하지만 추가한 schema 삭제는 자동 복구로 취급하지 않는다.
