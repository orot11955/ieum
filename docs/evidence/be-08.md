## 구현과 계약

- `business` migration 0004에 Context identity/current pointer와 불변 identity revision, Unit membership 이력, 명시적 Context/Thought 관계를 추가했다. Context identity revision과 membership revision, Unit membership version을 분리했다. workspace 포함 복합 FK, 5개 신규 테이블의 FORCE RLS, 필요한 열만 UPDATE하는 권한을 적용했다.
- Context 생성·rename/purpose/scope/kind 변경·archive·supersede를 구분하고 과거 identity revision을 조회한다. `SUPERSEDED`에는 같은 workspace의 active 대상을 요구하며 자기 자신은 DB 제약도 거부한다. 기본 목록은 active만 반환하고 `includeArchived=true`로 보관·대체 맥락을 재검색한다.
- Unit의 전체 소속 집합은 `baseVersion`을 요구하는 한 명령에서 교체한다. 다중 SECONDARY/BACKGROUND, 선택적 단일 PRIMARY를 지원한다. 변동된 소속은 종료 시각·사유를 남긴 뒤 새 row를 삽입한다. Unit row 잠금과 DB active pair/primary 부분 unique 제약으로 경쟁을 제어한다. 변경은 receipt·감사·참조만 담은 outbox와 같은 트랜잭션이다.
- Context의 `PARENT_OF`는 workspace advisory transaction lock과 recursive CTE로 순환을 거부한다. `RELATED_TO`, Thought의 `CONTRADICTS`/`RELATED_TO`는 대칭 endpoint를 정규화하고 중복을 막는다. `CONTRADICTS`는 독립된 승인 type으로 저장하며 무관계로 변환하지 않는다. relation은 승인자(actor)를 저장하고 생성·scoped 조회·종료를 지원한다. Thought relation은 실제 active/current Unit revision을 요구한다.
- Nest API는 세션·active OWNER·workspace·Origin/host를 확인한다. 읽기는 `Cache-Control: no-store`; Context 목록은 `(updated_at,id)` cursor로 페이지를 넘기고 이름 검색은 입력을 문자 그대로 찾는다. Zod/OpenAPI와 생성된 client 타입을 갱신했다. 다른 workspace 대상은 404로 숨긴다.

## 미검증·데이터 영향·복구

합성 계정과 격리 DB만 변경했다. 운영 데이터·실사용 Context 품질·브라우저 UI·검색 index와의 동기화는 미검증이다. Context 목록 페이지는 최대 50개(내부 상한 100개)이고, 개별 Context/Unit 관계 읽기는 해당 객체의 모든 연결을 반환하므로 매우 큰 객체의 응답 크기 평가는 후속 성능 검증 대상이다. BE-06 outbox worker가 아직 없어 membership 변경 event는 DB에만 안전하게 남는다. BE-11은 FE-02 선행이므로 웹 편집기 구현 전에는 시작할 수 없다.

운영 적용에는 기존 DB/role inventory, backup, 0004 migration rehearsal, 배포 순서와 별도 승인이 필요하다. 0004는 기존 ThoughtUnit에 기본값 1의 `membership_version`을 추가하고 신규 테이블만 생성한다. 운영 복구는 사전 백업과 별도 계획으로 수행하며 스키마 삭제를 자동 롤백으로 취급하지 않는다. BE-08 API는 0004 적용 후 배포해야 한다.
